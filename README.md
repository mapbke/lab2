## Файлы

- [run_demo.sql](run_demo.sql) — самостоятельный пример с тестовыми данными для проверки всех запросов. Использует отдельную схему `lab2_demo`, исходные таблицы первой работы не трогает.

## Как выполнить на базе из первой лабораторной

1. Открой базу `warehouse_lab_v6` в **pgAdmin 4 → Query Tool**.
2. Убедись, что там есть таблицы `warehouses` и `placements` (из `lab1/create_tables.sql` и `lab1/insert_data.sql`).
3. Открой и выполни [queries.sql](queries.sql). Для скриншотов выполняй каждое задание отдельно, выделяя нужный запрос в редакторе.
4. Пункты 3–6 меняют только производную таблицу `lab2_warehouses`. Исходные `warehouses` и `placements` не изменяются.

## Проверка с демонстрационными данными

В Query Tool выполни [run_demo.sql](run_demo.sql) целиком. Он создаёт изолированные таблицы в `lab2_demo`, добавляет данные (в том числе отгрузки 2008 года и склад без заведующего в Москве) и запускает семь запросов. При повторном запуске демонстрационные таблицы пересоздаются.

**Обрати внимание:** в исходном `lab1/insert_data.sql` нет отгрузок за 2008 год и нет склада Москвы с пустым полем заведующего. Поэтому на исходных данных пункт 2 возвращает пустой результат, а пункт 7 — нулевые суммы. Это корректное поведение запросов, не ошибка.

## Что делают запросы

1. Выбор номеров складов, не получавших товар в сентябре (`NOT EXISTS` и `EXTRACT`).
2. Выбор складов Москвы без заведующего (`WHERE`, `ILIKE`, `IS NULL`).
3. Создание таблицы с данными из запроса 1 (`CREATE TABLE AS`).
4. Добавление складов вне Москвы без дублей (`INSERT INTO ... SELECT`).
5. Утроение вместимости складов с чётными номерами (`UPDATE`).
6. Удаление из созданной таблицы складов без заведующего (`DELETE`).
7. Суммарный вес отгрузок 2008 года по каждому складу (`SUM`, `GROUP BY`, `LEFT JOIN`, `COALESCE`).

Для пункта 1 «сентябрь» рассматривается **без ограничения по году**, так как в условии год не указан. Для пункта 7 вес берётся из `placements.weight_kg` как вес записи об отгрузке.
